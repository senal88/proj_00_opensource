2. Script de monitoramento (check_channels.sh)
O script usa --flat-playlist --playlist-end 3 para consultar apenas os metadados leves dos 3 vídeos mais recentes e deduplica pelo ID do vídeo diretamente contra o urls.txt.

#!/usr/bin/env bash
set -euo pipefail

CHANNELS_FILE="${1:-channels.txt}"
URLS_FILE="${2:-urls.txt}"
LIMIT=3

if [[ ! -f "$CHANNELS_FILE" ]]; then
  echo "Erro: arquivo '${CHANNELS_FILE}' não encontrado." &2
  exit 1
fi

touch "$URLS_FILE"
NOVOS=0

while read -r domain channel_url; do
  [[ -z "${domain:-}" || "$domain" == \#* ]] && continue

  # Extrai apenas os IDs dos últimos N vídeos sem baixar mídia
  video_ids="$(yt-dlp --flat-playlist --playlist-end "$LIMIT" \
    --print "%(id)s" --no-warnings "$channel_url" 2/dev/null || true)"

  if [[ -z "$video_ids" ]]; then
    echo "[AVISO] Nenhum vídeo obtido de: ${channel_url}" &2
    continue
  fi

  while IFS= read -r vid; do
    [[ -z "$vid" ]] && continue
    # Deduplicação exata pelo ID do vídeo
    if ! grep -Fq "$vid" "$URLS_FILE"; then
      echo "${domain} https://www.youtube.com/watch?v=${vid}"  "$URLS_FILE"
      echo "[NOVO] ${domain} - https://www.youtube.com/watch?v=${vid}"
      NOVOS=$((NOVOS + 1))
    fi
  done  ./check_channels.log 2&1


]

# PROMPT — Radar Open Source & Engenharia Reversa (Skip, página única)

## 1. Objetivo

Construir uma página única, autocontida (HTML/CSS/JS, sem backend), chamada **Radar OS/RE**. Ela é um cockpit de curadoria com dois eixos de conteúdo:

- **self_hosted** — open source, self-hosted e alternativas gratuitas a SaaS.
- **reversa** — engenharia reversa, análise de baixo nível, binários e firmware.

A página organiza três coisas: as fontes de curadoria (canais e fontes primárias), o fluxo de captura de novos vídeos via CLI, e o radar de itens capturados com triagem (novo / avaliado / descartado). O uso típico é semanal: rodar o script, colar a saída, triar o que vira projeto ou estudo.

## 2. Regras invioláveis de conteúdo

1. **Não invente dado.** Título de vídeo, data, contagem, número de estrelas, licença, autor ou handle que não estejam na seção 5 são proibidos. Campo sem dado real aparece como `não informado` e editável.
2. **Nenhuma chamada de rede.** Zero `fetch`, zero CDN, zero fonte externa, zero API do YouTube. A página funciona aberta de dentro do arquivo.
3. **Link só na forma exata.** Canal: `https://www.youtube.com/@handle/videos`. Vídeo: `https://www.youtube.com/watch?v=`. Nunca gerar slug, nunca encurtar, nunca "corrigir" a URL recebida.
4. **Sem número agregado inventado.** Contadores ("12 itens", "3 novos") só refletem dados realmente carregados na sessão.
5. **Estado vazio é conteúdo.** Onde não há dado, mostrar bloco explicando o que fazer para popular — não preencher com exemplo fictício.
6. **Sem selos ou carimbos sobre o próprio documento.** Nada de "BETA", "DRAFT" ou marca d'água sobre o cabeçalho.
7. **Uma ideia por tela.** Cada aba responde a uma pergunta só.

## 3. Estrutura — quatro abas

### 3.1 Radar

Cockpit principal, com duas subvisões: **Vídeos** e **Projetos**.

Barra fixa no topo da aba:
- campo de busca (filtra por título, canal, ID e tags)
- filtro de domínio: todos / `self_hosted` / `reversa`
- filtro de canal (dropdown com os canais que existem nos dados carregados)
- filtro de status: todos / novo / avaliado / descartado
- contador à direita, no formato `N itens · M novos`

Cada item de vídeo é uma linha/card com: ID do vídeo em monoespaçado, domínio (cor do eixo), canal, título, data de captura, link abrível e três ações — **abrir**, **copiar link**, **marcar visto**. Itens não vistos recebem um marcador discreto à esquerda (barra de 3px na cor do domínio), nunca um badge sobre o texto.

Subvisão **Projetos**: tabela de repositórios triados, com colunas nome, URL, categoria (self-hosted / CLI / firmware / malware-analysis / outra), licença, origem (qual canal ou fonte primária trouxe), veredito (usar / testar / descartar) e nota curta. Botão **Adicionar projeto** abre formulário inline; valida que a URL começa com `https://github.com/` ou `https://` e que nome não está vazio.

Ferramentas de entrada, no rodapé da aba:
- **Importar urls.txt** — textarea que recebe o conteúdo do arquivo gerado pelo script. Parser: ignora linhas vazias e iniciadas com `#`, lê `dominio url`, extrai o ID por regex `[?&]v=([A-Za-z0-9_-]{11})`, descarta duplicados por ID e marca cada novo item como `novo`.
- **Exportar JSON** e **Limpar dados** (com confirmação explícita em dois passos).

### 3.2 Canais

Tabela curada com colunas: canal, região/idioma, domínio, foco, por que seguir, link.

- O link aparece clicável quando verificável; quando o handle não foi informado, a célula mostra `handle não informado` em texto secundário com botão **editar** que abre campo inline. O valor digitado persiste.
- Cada linha tem um checkbox **monitorar**. O checkbox só fica habilitado se o canal tiver URL válida.
- Botão **Gerar channels.txt** monta o arquivo a partir dos canais marcados, no formato exato ` /videos`, uma linha por canal, com comentário de cabeçalho `# Formato:  `. Dois botões de saída: **copiar** e **baixar**.

### 3.3 Fontes primárias

Lista ordenada por prioridade, com nome, o que entrega, cadência, tipo (RSS / CLI / newsletter / diretório) e link. Bloco de abertura explicando a lógica: monitorar aqui captura o projeto antes de ele virar vídeo, o que dá vantagem de tempo sobre quem só consome YouTube.

### 3.4 Pipeline

Documentação operacional do script, em quatro blocos copiáveis e independentes:

1. **channels.txt** — exemplo mínimo com três canais do catálogo.
2. **check_channels.sh** — o script completo, verbatim, conforme seção 6.
3. **Instalação e validação** — `chmod +x`, primeira execução, segunda execução com saída esperada `Novos vídeos adicionados em urls.txt: 0`.
4. **Agendamento** — linha de cron com seletor de plataforma: macOS usa `/opt/homebrew/bin/bash`, Linux usa `/usr/bin/bash`. O bloco copiado respeita a plataforma selecionada.

Notas técnicas obrigatórias no rodapé da aba: dependência de `yt-dlp`; `--flat-playlist --playlist-end 3` não baixa mídia; deduplicação é por ID; e o alerta de que `grep -Fq "$vid"` casa substring em qualquer parte do arquivo — em produção prefira casar o campo exato, por exemplo `grep -Fq "watch?v=${vid}"`.

## 7. Comportamento e persistência

- Persistir em `localStorage` sob a chave `radar-os-re/v1`: vídeos, projetos, overrides de canais (handle e título editados), preferência de plataforma no cron e último estado dos filtros.
- Importação é idempotente: reimportar o mesmo `urls.txt` não cria duplicata e não zera o status já atribuído.
- Ordenação padrão do feed: data de captura decrescente, depois ID.
- Toda ação destrutiva (limpar dados, remover projeto) exige confirmação em dois passos.
- Atalhos de teclado: `/` foca a busca, `Esc` limpa, `1`–`4` troca de aba.
- Sem truncamento silencioso: listas longas rolam, nunca cortam com "ver mais" que esconde itens.

## 8. Identidade visual e UX

- Tema escuro fixo, alto contraste. Tipografia de sistema para texto e monoespaçada para IDs, comandos e caminhos.
- Dois acentos, um por eixo: âmbar para `self_hosted`, ciano para `reversa`. Usar o acento em barra lateral, marcador e filtro ativo — nunca em texto corrido inteiro.
- Hierarquia por espaço e peso, não por caixas com sombra em tudo. Nada de gradiente decorativo, nada de ícone de enfeite.
- Tabelas viram cards empilhados abaixo de 720px, preservando link e ações.
- Contraste mínimo AA, `:focus-visible` visível em todos os controles, `aria-label` nos botões de ícone.
- Renderização instantânea no primeiro paint, sem tela de carregamento.
